# Mockup

기기 목업 안에 화면을 **원근(perspective)에 맞춰** 끼워넣는 피그마 플러그인.

피그마엔 perspective 변형이 없다. 그래서 목업의 스크린 면(4점 벡터)의 좌표를 읽어
래스터를 미리 워핑한 뒤 image fill로 넣는 방식으로 동작한다.

## 설치

1. Figma 데스크톱 앱 → **Plugins → Development → Import plugin from manifest…**
2. 이 폴더의 `manifest.json` 선택

이후 **Plugins → Development → Mockup**으로 실행. 계정에 종속되므로 이 맥에서만
보인다. 팀에 배포하려면 Community 게시(리뷰 필요) 또는 Organization 전용 배포가 필요하다.

## 사용

1. **목업**(또는 그 안의 스크린 레이어)과 **넣을 화면** 두 개를 선택
2. 플러그인 창에서 인식된 화면/소스 확인 → 필요하면 **역할 바꾸기**
3. **화면 넣기**

| 옵션 | 설명 |
|---|---|
| 배율 | 출력 해상도 배수. 2x면 대개 충분 |
| 회전 / 반전 | 결과가 돌아가거나 뒤집혔을 때만 사용 (원근 목업 전용) |
| 이미지로 굽기 | 기본. 래스터로 구워 image fill로 넣는다 |
| 프레임 그대로 | 평면 목업 전용. 소스를 **살아있는 프레임 그대로** 얹는다 |
| 되돌리기 | 직전 이미지로 복구 (원본 해시를 레이어에 기록해둔다) |

## 목업 두 종류

플러그인은 스크린 면의 성격을 보고 알아서 갈라진다.

| | 원근 목업 | 평면 목업 |
|---|---|---|
| 스크린 면 | 네 변 길이가 다른 4점 VECTOR | RECTANGLE 등 자기 좌표계에선 직사각형 |
| 필요한 변환 | 호모그래피 (아핀 아님) | 아핀 (회전·크기·기울임까지) |
| 처리 | 워핑해서 굽는다 | 워핑 불필요 — fill만 넣으면 정확 |
| 프레임 그대로 | ✗ | ✓ |

평면 목업은 기기가 회전해 있어도 상관없다. 회전은 노드 자체의 transform이 처리하므로
스크린의 로컬 좌표계에선 여전히 직사각형이다.

## 어떻게 동작하나

- **스크린 면 자동 탐색** — `👈`로 이름 붙은 레이어를 최우선으로 찾는다(모든 목업 킷의
  관례). 없으면 진짜 원근 쿼드를 찾고, 그것도 없으면 사용자가 직접 가리킨 노드만 쓴다.
  평면 목업은 사각형이 널려 있어서 "제일 큰 사각형"으로 추측하면 기기 몸체를 집는다.
- **평면은 굳이 워핑하지 않는다** — 4점이 두 개의 x값·두 개의 y값에 맞아떨어지면
  직사각형이므로 image fill이 이미 정확히 그 자리에 들어간다. 리샘플링을 한 번 덜 하니
  결과도 더 선명하다.
- **코너 역할 자동 판별** — 쿼드의 와인딩을 정규화하고, 마주보는 두 변 쌍 중
  **소스의 종횡비에 맞는 쪽**을 위/아래로 잡는다. 세로형·가로형 목업 모두 대응.
- **해상도 자동 결정** — 쿼드의 최장 변을 1:1로 덮을 만큼만 `exportAsync`로 내보낸다.
  확대 흐림도, 낭비도 없다. (최대 4x)
- **워핑** — dest→src 호모그래피를 풀어 출력 픽셀마다 역매핑. 2×2 서브샘플을
  프리멀티플라이 공간에서 평균내므로 가장자리에 색 번짐이 없다.

## 테스트

```bash
test/run.sh
```

`ui.html`의 `<script id="warp-core">` 블록을 **그대로 꺼내서** 돌리므로, 사본이 아니라
실제 배포되는 코드를 검증한다. node가 있으면 node로, 없으면 macOS 기본 탑재
JavaScriptCore로 실행된다.

검증 항목:
- 실제 목업 4종(세로 좌·우 기울기, 가로형, 역방향 와인딩)의 코너 역할 배정
- 호모그래피가 네 코너를 오차 1e-6 미만으로 왕복하는지
- 퇴화 쿼드·곡선 패스 거부
- 랜드마크 패턴을 워핑해 네 모서리가 제자리에 가는지, 쿼드 **밖은 전부 투명**하고
  **안은 빈 곳이 없는지** (샘플링이 아니라 전 픽셀 검사)
- `~/.claude/skills/figma-mockup`의 파이썬 레퍼런스와 교차 대조 — 보간 커널이 달라
  경계 1픽셀은 다를 수밖에 없으므로, **불일치가 전부 경계에 몰려 있는지**와
  내부 색 차이를 본다

## 한계

- **원근 목업은 반드시 래스터로 구워진다.** 벡터로 남길 수 없다. 호모그래피는 직선은
  직선으로 보내지만 베지어 곡선은 *유리* 베지어로 보내는데 Figma엔 그런 게 없고, 획은
  원근에서 멀어질수록 가늘어져야 하는데 Figma 획은 굵기가 균일하며, 그라디언트 변환은
  아핀만 지원한다. 텍스트도 아웃라인으로 만들어야 한다. 즉 "그대로"가 성립하지 않는다.
  평면 목업이라면 **프레임 그대로**를 쓰면 된다.
- 원근 목업은 소스 프레임을 고쳐도 자동 반영되지 않으니 다시 실행해야 한다.
- 스크린 면은 평면이어야 한다. 곡면(폴더블 힌지 등)은 지원하지 않는다.
- 원근 스크린 면은 4점 직선 패스여야 한다. 모서리가 둥글게 깎인 벡터는 인식하지 못하니
  그 경우 사각형 스크린 레이어를 직접 선택할 것.
- Figma 이미지 상한 때문에 출력이 4096px를 넘으면 거부한다. 배율을 낮출 것.
- 기존 스크린 이미지에 구워져 있던 펀치홀 카메라·상태바는 함께 교체된다.

## 파일

```
branding/        커버·아이콘 + 배포용 카피 (LISTING.md)
manifest.json    플러그인 매니페스트
code.js          플러그인 샌드박스 — 선택 분석, exportAsync, createImage
ui.html          UI + 워핑 코어 (샌드박스엔 canvas가 없어 여기서 처리)
test/verify.js   코어 검증 (node / jsc 양쪽 실행)
test/run.sh      픽스처 생성 + 테스트 실행
```
